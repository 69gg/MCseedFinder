# GPU 加速

MCSeed Finder 的 GPU 后端面向 Linux x86_64，支持 NVIDIA CUDA 和 AMD ROCm/HIP。默认 CPU 构建没有 GPU 运行时依赖；CUDA 与 ROCm 是互斥的可选 Cargo feature。

## 构建

CUDA 构建需要可用的 CUDA Toolkit 和 `nvcc`：

```bash
cargo build --release --features cuda
```

构建脚本从 `PATH` 查找 `nvcc`。非标准安装可以设置 `NVCC=/path/to/nvcc`。程序运行时还需要与该 Toolkit 兼容的 NVIDIA 驱动。

ROCm 构建需要 ROCm HIP SDK 和 `hipcc`：

```bash
cargo build --release --features rocm
```

构建脚本依次使用 `HIPCC`、`PATH` 定位编译器，并通过 `ROCM_PATH`、`HIP_PATH`、`hipconfig --path` 或编译器位置发现 `libamdhip64`。例如：

```bash
HIPCC=/opt/rocm/bin/hipcc cargo build --release --features rocm
```

当前若为非 Linux x86_64 目标，启用 GPU feature 会在构建期给出明确错误；不启用 feature 的 CPU 版本不受这个限制。不要同时启用 `cuda,rocm`。

## 使用

GPU 变体默认采用自动模式：

```bash
mcseed-finder find \
  --random \
  --count 10 \
  --accelerator auto \
  --structure-near village:256
```

自动模式只有在以下条件都成立时才启用 GPU：

- 二进制包含 CUDA 或 ROCm 后端；
- 运行时检测到设备；
- 查询包含至少一个可安全下推的结构放置必要条件。

否则它会在 stderr 说明原因并回退多线程 CPU。需要严格要求某个后端时，显式使用 `--accelerator cuda` 或 `--accelerator rocm`；这时不会静默回退。`--gpu-device N` 选择设备，默认是 0。

JSON 对应字段位于 `search`：

```json
{
  "search": {
    "accelerator": "rocm",
    "gpu_device": 0,
    "threads": 12,
    "batch_size": 4096
  }
}
```

`hip` 也可作为 `rocm` 的输入别名。

## 正确性模型

GPU 执行精确出生点估算和保守结构放置筛选；最终世界条件仍由原生 CPU 路径确认：

1. CPU 按遍历顺序生成种子。GPU 首先使用出生算法的严格原点包络检查正向结构条件和共享出生点所必需的结构对关系；当前配置的主世界上界是 2697 格，下界投影上界是 340 格。这个阶段完全不计算出生点。
2. 不能直接假设出生点为 `(0, 0)`：合法出生点可能离原点数千格。第一阶段只在“任何合法出生点都不可能满足条件”时淘汰，因此不会把远离原点但有效的种子漏掉。
3. 对幸存种子，GPU 用 64 线程专用核只扫描 Mojang 出生点估算的外层候选。每个 Perlin octave 独立初始化，候选按适应度和原始遍历序号归约；外层状态留在显存，后续内层无需重新生成排列数组。
4. 外层胜者到最终出生点的严格上界来自活动版本配置：内层半径 512 格、区块中心取整 12 格、地表细化 125 格，合计 649 格；下界投影安全换算为 84 格。GPU 以外层胜者为锚点执行扩大半径结构筛选，并检查多个主世界结构及其 `/8` 下界结构是否可能围绕同一出生点共存。
5. 只有通过外层联合几何筛选的种子才进入 256 线程内层搜索。内层从缓存的 Perlin 状态和外层胜者继续，所得完整估计点与 CPU 参考逐种子一致；随后用 125/18 格包络做更精确的结构粗筛。
6. 对现代同心环要塞，GPU 复现 Java LCG、环数推进和 128 个近似位置。距离判断按每轴扩张“生物群系定位上界 + 设备三角函数舍入余量”；不与包络相交才会淘汰，因此该阶段不把近似位置当成实际要塞。
7. 对 `end_gateway` 锚点，GPU 复现首轮洗牌决定的第一座主岛折跃门方向，并以名义 1024 格出口为中心，把条件半径扩大活动版本声明的 320 格严格包络。包络覆盖沿射线寻找非空区块、区块内候选偏移和 33×33 最高地形搜索；它只负责无漏筛，真实外岛出口由 CPU 末地地形算法确定。
8. CPU 从已保存的完整估计点继续执行带地表落脚检查的出生点细化，不会再次运行估算搜索。GPU 随后用原始出生点半径精筛；固定坐标和末地折跃门条件不需要这一级出生点准备。
9. 最终幸存种子回到原有 Cubiomes 路径，完整检查生物群系、地形、结构竞争、Jigsaw 布局、末地要塞眼数与末地折跃门真实出口等条件。只有 CPU 精确路径通过的种子才会输出；已生成的出生点和折跃门出口会在报告阶段复用。

出生点估算保持活动版本配置的候选顺序和单精度角度/半径推进方式，并逐级计算严格下界：先检查到原点的距离，再检查偏移与怪异度、陆地性，只有仍可能优于当前最优解时才采样其余气候噪声。内层搜索按最多 256 个候选分块，每块归约出的更优阈值会用于下一块，减少昂贵的双精度采样。该优化只省略不可能获胜的计算，不改变相等值的先后选择规则。

噪声种子、octave、幅度、搜索半径和适应度规则由 `native/version.h` 选择的能力配置提供，Rust 调度层不比较版本字符串。新增版本只有在显式声明兼容配置后才启用 GPU 出生点估算，否则继续使用已有 CPU 路径。HIP 使用 `-ffp-contract=off`，CUDA 使用 `--fmad=false`，防止融合乘加改变临界舍入；设备测试会逐种子与 CPU 估算坐标比较。

随机分区放置参数来自 `native/bridge.c` 的现有结构注册表与 Cubiomes 版本配置；强要塞数量、距离、扩散，以及首个末地折跃门的名义距离和误差包络均由 `native/version.h` 的活动版本能力配置提供。CPU 参考实现和 CUDA/HIP 内核共享 `native/gpu/placement.h`。原生测试会逐分区比较全部随机放置白名单与 Cubiomes、逐种子验证折跃门真实出口落在 GPU 包络内，并把优化后的强要塞扫描和不剪枝的 128 次定位逐坐标比较；装有 GPU SDK/设备时还会逐字节比较设备内核与 CPU 参考掩码。

结构放置算法采用显式白名单映射；以后新增但尚未确认放置语义的结构默认留在 CPU 路径，不会猜测其兼容性。

当前可下推 22 个结构族中的 20 个随机分区放置族和现代同心环要塞。废弃矿井不使用已实现的放置模型，因此不下推。以下逻辑也会保留在 CPU：

- 生物群系、完整地形和出生生物群系；
- 最近要塞与末地传送门已有眼数；
- Jigsaw 或其他结构内部部件的最终判断；
- `any`、`not`，以及只有最大数量的排除条件。

正向子部件条件可以安全下推“父结构候选必须存在”这一必要条件，但部件本身仍由 CPU 生成并验证。若一个“任一结构”条件中含有无法下推的结构族，整个条件不会部分下推，以防漏解。

## 性能

GPU 对半径较小、放置候选稀少、后续生物群系或子结构校验昂贵的组合最有效。只有出生生物群系、要塞眼数，或半径大到几乎每个种子都有候选时，GPU 可能没有收益；自动模式会跳过完全不可加速的查询，但不会尝试根据未知硬件自动预测盈亏。

同一查询的结构对预筛、粗筛和精筛会分别按扫描面积与估计放置密度排序，让更可能淘汰候选的条件先执行并尽早结束当前线程。强要塞环需要按种子顺序推进随机状态，因此会排在便宜的随机分区条件之后，并在不同种子之间由 GPU 并行；它不会进入不适用的随机分区结构对扫描。这些调整只重排必须同时成立的必要条件，不影响筛选语义。

`--threads` 在 GPU 模式下控制幸存者出生点细化和精确复核并行度，通常保留系统默认值即可。细化任务会拆成多于线程数的小分片并通过共享队列动态领取，少量候选搜索路径较长时，已空闲的核心可以继续处理剩余分片。

`--batch-size` 默认 4096；更大的批次会向 GPU 提供更多独立种子并摊薄固定开销，但会增加内存占用、进度刷新间隔和找到足够结果后的停止延迟。分级出生点管线会尝试为每个外层候选缓存活动版本的 Perlin 状态；当前配置约为每个候选 14 KiB，分配失败时会安全回退到为内层幸存者重新初始化。10 GB RX 6750 GRE 上，这类出生点重查询的实测最佳区间约为 20000–40000；`120000` 可运行但不一定更快。不同 GPU 应以固定 `--random-seed` 和 `--max-attempts` 做短基准，不要仅凭显存把批次调到最大。

进度与完成摘要会分别显示出生点前结构预筛、外层出生点估算、外层联合粗筛、内层出生点细化、完整估计点粗筛、地表细化、原半径精筛和 CPU 完整验证耗时，并报告各级保留数/原始候选数。

## 验证

默认 CPU 路径：

```bash
cargo test --offline
cargo clippy --all-targets --offline -- -D warnings
```

对应 GPU SDK 已安装时：

```bash
cargo test --offline --features cuda
cargo clippy --all-targets --offline --features cuda -- -D warnings

cargo test --offline --features rocm
cargo clippy --all-targets --offline --features rocm -- -D warnings
```

日常 GPU 测试只使用固定小样本，比较 CPU/GPU 出生点、随机分区和强要塞包络掩码、强要塞精确命中的保守性以及跨批次最终结果；不会启动大范围随机搜索。另有默认忽略的 10000 种子精确对照，可在性能验证时显式运行：

```bash
cargo test --release --features rocm \
  compiled_gpu_spawn_estimator_matches_cpu_for_ten_thousand_seeds \
  -- --ignored --nocapture
```
